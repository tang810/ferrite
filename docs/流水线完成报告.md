# 横向屏蔽中心场与 IntH2 导出完成报告

2026-05-27，分支 `experiment-completion-pipeline`

## 背景

目标是给多层圆柱薄铁氧体磁屏蔽建一套可复现的仿真-导出-后处理流水线。之前有 AEDT 工程和历史数据，但三个问题卡住了：

一是所有 shield 工程用的都是 torus/current（铜环+电流）近似外场，而 B0_reference_x 用的是 x 向切向 H 场，物理上不是一回事，SF 没法直接比。二是没有能从 AEDT 自动提取中心场和 IntH2 的 ScriptEnv 脚本。三是导出后的 build_dataset → compute_metrics → validate_layerwise 链路没串起来。

## 做了什么

写了一个 ScriptEnv 脚本 `scripts/aedt_export/rebuild_shields_tangentialH.py`，在 AEDT 里用 IronPython 2.7 跑。每个 shield 工程走 9 步：删 .aedt.lock → 打开工程 → 删旧的 Torus/Current 边界和激励 → 删 Torus、Iext 电流片等旧几何体 → 确保铁氧体材料是 ferrite 不是 vacuum → 在 Box1 的 y/z 面加 x 向切向 H (H0=1 A/m)，x 端面加零切向 H → 验证设计并求解 Setup1 → 导出中心场 Bx/By/Bz/Mag → 导出 IntH2_total 和各层 IntH2_Li。

切向 H 的分配逻辑：classify_box_faces() 按 Box1 每个面中心坐标绝对值最大的轴判断法向，y/z 面加 x 向切向 H，x 面加零切向 H 作开放磁通边界。跟 B0_reference_x 的设置一致。

分两批跑了 7 个 case。第一批单层：C1_N1_t008_x, t020_x, t040_x, t060_x。第二批多层：C2_N2_t020_g010_x (N=2), C2_N3_t020_g010_x (N=3), C2_N4_t015_g008_x (N=4)。

导出完后跑后处理流水线：build_dataset.py（合并 B0 和 Bcenter，算 SFx = |B0_Bx|/|Bcenter_Bx|）→ compute_metrics.py（算 Vf, etaS = ln(SFx)/Vf 等衍生指标）→ validate_layerwise_intH2.py（校验 |IntH2_total - sum(Li)|/|total| < 1e-3）。

## 踩过的坑

第一个坑：所有 OpenProject 都失败。原因是 .aedt.lock 文件残留，AEDT 以为工程还被占着。在 process_case() 开头加了 lock 检测和删除就好了。

第二个坑：IronPython 2.7 的 open() 只接受 (path, mode, buffering) 三个参数，不能传 newline 和 encoding。csv.DictWriter 在 IronPython 2.7 下要 binary mode ("wb"/"ab")。

第三个坑：多层 case 的 IntH2_L1 错误地等于了 IntH2_total。原因是单层时 L1=total 是对的，所以我把 IntH2_total 放在了 L1 的候选列表里，但多层时这个 fallback 就不对了。改成按 layers==1 vs layers>1 分支，多层时 L1 候选里拿掉 IntH2_total。

第四个坑：模板工程里 IntH2 的命名表达式用的是历史名字（IntH2_cyl2/cyl4, IntH2_s1-s4, InH2_s4 注意是 In 不是 Int），不是规范名 IntH2_Li。实现了一个按层号试多个 legacy name 的 fallback 机制。

## 结果

B0_reference_x 验证：B0_Bx_T = 1.2566e-06 T，比最大横向分量大 6.47e+06 倍，确认是纯 x 向外场。

7 个 case 的结果：

- C1_N1_t008_x: N=1, t=0.08mm, SFx=1.256, Vf=10057mm³, etaS=2.26e-05
- C1_N1_t020_x: N=1, t=0.20mm, SFx=1.499, Vf=25158mm³, etaS=1.61e-05
- C1_N1_t040_x: N=1, t=0.40mm, SFx=2.135, Vf=50366mm³, etaS=1.51e-05
- C1_N1_t060_x: N=1, t=0.60mm, SFx=2.806, Vf=75624mm³, etaS=1.36e-05
- C2_N2_t020_g010_x: N=2, t=0.20mm, g=0.10mm, SFx=2.235, Vf=50391mm³, etaS=1.60e-05
- C2_N3_t020_g010_x: N=3, t=0.20mm, g=0.10mm, SFx=2.878, Vf=75700mm³, etaS=1.40e-05
- C2_N4_t015_g008_x: N=4, t=0.15mm, g=0.08mm, SFx=3.750, Vf=75715mm³, etaS=1.75e-05

全部 metric_status=processed, SFx>1, 分层 IntH2 校验 passed, used_in_paper=no。

趋势上看：单层 SFx 随厚度单调递增。总铁氧体量相近时，N=4 (SFx=3.750) 比 N=1 (SFx=2.806) 好，多层确实有效。etaS 都在 ~1e-05 量级，一致性没问题。

## 技术备注

IronPython 2.7 的 open() 只有 (path, mode, buffering)，没有 newline 和 encoding。ScriptEnv 入口固定为 `import ScriptEnv; ScriptEnv.Initialize("Ansoft.ElectronicsDesktop")`。

FieldsReporter 计算器两条路径：场量用 CalcStack("clear") → EnterQty("B") → CalcOp("ScalarX") → EnterPoint(name) → CalcOp("Value") → GetTopEntryValue(SOLN, [])；命名表达式用 CopyNamedExprToStack(name) → ClcEval(SOLN, []) → GetTopEntryValue(SOLN, [])。

Legacy 命名：旧工程里 IntH2 的命名不统一，有 IntH2_cyl2/cyl4, IntH2_s1-s4, InH2_s4（注意 In 不是 Int）。导出时要 fallback 到这些名字，新建工程统一用 IntH2_Li。
