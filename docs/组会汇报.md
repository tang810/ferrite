## 二、我发现并解决了三个关键问题

### 问题 1：旧 B0 参考数据方向错误

算屏蔽因子需要无屏蔽参考场 B0。我翻了旧数据，发现 C1_N1_t008 行的 B0 导出有明显问题：B0_Bx = -1.65e-08 T，B0_Bz = 3.33e-08 T。对 x 向外场来说 z 分量比 x 分量还大一倍，方向完全不对。用这组数据算出来的 SF 只有 0.6265——铁氧体不可能放大外场，物理上不合理。

我的判断是旧 B0 不可用，需要重建。我从单层 shield 工程复制模板，把铁氧体改成 vacuum，删掉旧的 torus/current 激励，在空气盒表面施加 x 向切向 H 边界条件（H0=1 A/m），静磁求解。

重建后的 B0_reference_x：
- B0_Bx = 1.2566e-06 T
- 方向比 |Bx|/max(|By|,|Bz|) = 6.47×10⁶
- 确认是纯 x 向外场

### 问题 2：shield 工程和 B0 参考用了不同的物理边界条件

B0 有了，但 shield 工程里的外场设置是不是同一套？我读了历史运行日志，发现所有 7 个 shield 工程的外场都是 torus/current 方式——在铁氧体外面画铜环通 1A 电流产生磁场，还配了辅助电流片。

torus/current（电流源激励）和 tangential-H（直接约束边界 H 场）是两种不同物理问题的边界条件。在两种不同的外部场设置下，屏蔽体内部的场分布不一样。这意味着旧 shield 工程算出来的 Bcenter 不能直接跟 B0_reference_x 比——它们不来自同一个物理问题。这就是旧数据 SF<1 的根本原因。

结论：7 个工程必须全部重建，统一改成 x 向切向 H。

### 问题 3：网格不够，薄层没剖分到位

重建跑完后数据看起来合理，担忧——最薄层只有 0.08mm，空气盒 200mm 量级，差了三个数量级，默认自适应网格在铁氧体薄层厚度方向到底放了几层单元？

我写了网格收敛性脚本，选了两个代表性 case（最薄的 C1_N1_t008_x 和最优的 C2_N4_t015_g008_x），各跑 coarse/medium/fine 三级。结果验证了我的担忧：

C1_N1_t008_x 的粗网格（MaxLength=0.08mm）SFx=1.356，但加密到 medium（0.027mm）和 fine（0.016mm）后 SFx 收敛到 1.340。粗网格比收敛值偏差 1.2%。C2_N4 收敛性好很多，粗网格就已收敛。

关键结论：对最薄层 case，默认自适应网格不够。所有 7 个 case 需要用 medium mesh（MaxLength = 层厚/3）统一重算。重算正在跑。

## 三、仿真的具体设置



**外场施加方式**：在空气盒 Box1 的 y/z 法向面上施加 x 向切向 H 场（H0=1 A/m），x 端面设零切向 H（开放磁通边界）。这等效于理想 Helmholtz 线圈产生的均匀场，是标准的测量标定配置。

**屏蔽因子定义**：SFx = |B0_Bx| / |Bcenter_Bx|，用方向分量而不是矢量模。因为 B0 已验证是纯 x 向，用分量算可以避免 y/z 方向噪声的污染。旧的用 Mag_B 算 SF 是一个方法论上的缺陷。

**虚拟 pickup 线圈模型**：在中心放一个半径 2.5mm、1 匝、1A 的小线圈，算铁氧体内的 ∫H²dV（记为 IntH2）。这个量通过波动耗散定理跟磁噪声谱密度关联，是一个几何因子——隔离了材料参数（μr″、电导率）之后的纯几何贡献。

**网格设置**：每层铁氧体单独加 LengthBased 网格操作，MaxLength = 层厚/3。表面和体内各一个。收敛性已验证——medium 到 fine 变化在 10⁻¹⁰ 量级。

**材料参数**：μr′=1000，σ=0.01 S/m（Mn-Zn 铁氧体 PC95 参考值）。这些是筛选参数，等拿到实测材料数据后替换。

## 四、脚本踩过的坑

这部分简单讲，主要是 IronPython 2.7 在 AEDT 里的限制

1. **lock 文件残留**：AEDT 非正常退出后 .aedt.lock 不清理，ScriptEnv 的 OpenProject 不会像 GUI 那样弹对话框，直接抛异常。在打开前手动删 lock 解决。

2. **IronPython 2.7 的 open() 只接受 3 个参数**：不能传 newline 和 encoding。CSV 必须用 binary mode "wb"/"ab" 写——这和 CPython 3 相反。

3. **多层 IntH2_L1 错误等于了 total**：单层时 L1=total 的逻辑是对的，但 fallback 列表被多层继承了，导致 L1 找不到 IntH2_L1 时就取了 IntH2_total。按 layers==1 和 layers>1 分支处理解决。

4. **旧工程命名表达式不规范**：有 IntH2_cyl2/cyl4、IntH2_s1-s4，甚至有 "InH2_s4"（手动输入时少打了 t）。给每层做了 multi-candidate fallback。

## 七、论文



论文目前的定位和主要论点：

- **不是**单纯报告"四层比单层好"
- **而是**建立一套方法：标定过的无屏蔽参考 → 方向性屏蔽因子 → 虚拟线圈 IntH2 → 层分辨分析 → 不确定性传播
- 核心 novelty：把方向性 SF、铁氧体体积、层分辨 IntH2 三个维度放在一个统一的、经过参考场验证的评估框架里
- 比较对象：表格对比了各工作的测量量、方法、噪声指标和局限性

目前论文状态：

## 九、关于网格问题的教训

这个网格问题我觉得值得单独说一下。第一批数据跑完后趋势看起来合理——SFx>1、单调递增、多层优于单层。所有指标都"通过"，很容易让人觉得数据没问题。

但 0.08mm 的薄层在 200mm 的空气域里，默认网格到底能不能剖分到位，后来专门跑了收敛性验证，证明确实有问题——最薄层的 SFx 偏差 1.2%，IntH2 偏差 0.5%。

数值不大，一个不能证明网格收敛的仿真结果是站不住脚的
